# S11 operating checklist — multiplatform distribution

## Intake and upstream gates
- [ ] Name the project, source asset, source version and accountable owner.
- [ ] Select the platform and exact surface; do not use a generic “social algorithm” setting.
- [ ] Resolve material health statements to current S02 claim IDs and Fact Lock statuses.
- [ ] Resolve audience, behavior objective, key message and CTA to S03.
- [ ] Record rights, consent, brand authority, privacy classification and accessibility needs.
- [ ] Mark unknown analytics, dashboard fields, API availability and platform rules as NOT_CHECKED or MISSING.

## S11-A Editorial Intelligence
- [ ] Select a hook formula for the objective; explain why it fits the audience.
- [ ] Review the spoken hook and on-screen hook as a semantically aligned pair.
- [ ] Use the native Promkes beat-sheet and motion contracts; add only a social-retention annotation layer.
- [ ] Run caption lint against a dated platform/surface profile, not a universal character limit.
- [ ] Reject sensationalism, misleading curiosity gaps, stigma, unsupported health claims and removed safety caveats.
- [ ] Apply the correct scoped institutional voice profile.

## S11-B Format Engineering
- [ ] Produce independent platform/surface versions; do not merely crop or cross-post.
- [ ] Confirm first-frame/cover/title, text safe area, reading time, subtitle accuracy and visual hierarchy.
- [ ] Check carousel sequence, one core idea per card, cited facts, alt text and final actionable CTA.
- [ ] Check Story sequence, sticker purpose, privacy-safe wording and moderation plan.
- [ ] Check long-form versus short-form viewer promise and end-screen/series continuity where relevant.

## S11-C Platform Intelligence & Planning
- [ ] Check official platform references and date; retain old observations separately from accepted baselines.
- [ ] Use user-supplied or authorized dashboard exports only.
- [ ] For every rate, store numerator, denominator, cohort, format, window, missingness and source.
- [ ] Keep competitor comparison manual, public, authorized and denominator-compatible.
- [ ] Build the calendar from campaign priorities, staff capacity, review windows and service hours; never force a universal posting frequency.
- [ ] Audit official profile identity, contact path, accessibility, pinned/featured information and currency.

## S11-D Community & Service Interaction
- [ ] Draft comments that add useful context, not engagement bait or repetitive promotion.
- [ ] Triage questions, misinformation, complaints, personal health details and urgent matters.
- [ ] Escalate clinical, emergency, safeguarding, legal and institutional matters to named human channels.
- [ ] Reply only within approved public information and current sources.
- [ ] DM only in response to user-initiated contact or explicitly consented/authorized keyword workflow.
- [ ] Never diagnose, collect unnecessary personal health information or send unsolicited bulk messages.

## S11-E Repurposing & Learning
- [ ] Preserve source, attribution, claim IDs, evidence status, date validity and rights on every derivative.
- [ ] Add substantive original explanation when adapting third-party content; do not represent minor edits as original.
- [ ] Humanize language without altering medical terms, quantities, names, units, local script or valid Unicode sequences.
- [ ] Keep voice profiles scoped by institution, channel, audience and version.
- [ ] Store only minimum necessary operational analytics; exclude patient/user identifiers and personal health data.
- [ ] Mark incomplete media inspection, absent analytics and unexecuted tests as NOT_RUN/NOT_VERIFIED.

## Handoff and release
- [ ] Route source/claim changes to S01/S02, campaign changes to S03, narrative changes to S04 and cross-domain changes through M00/S14.
- [ ] Submit the publication package for independent S12 QA.
- [ ] Record human approval, publication authorization and actual posting state separately.
- [ ] Never claim virality, ranking lift, improved health behavior or platform support without matching evidence.

## Bounded internal procedures
Editorial Intelligence; Hook Review; Hook Pair Composer; Social Beat Overlay; Caption Linter; Carousel Compiler; Story Planner; Profile Auditor; Editorial Calendar; Competitor Content Review; Performance Auditor; Comment Assistant; Reply Triage; DM Response Assistant; Repurposing Compiler; Language Quality Review; Voice Profile; Social Learning Ledger.

These are procedures owned by S11, not independent agents, background services, schedulers, account integrations or autonomous platform operators.
