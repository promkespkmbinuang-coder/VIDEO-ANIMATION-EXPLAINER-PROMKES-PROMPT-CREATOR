# M00 V4.0 — Executable validator and gate engine

**Implementation:** deterministic Python engine; 21 unique control IDs across eight sequential gates. Unit fixtures are synthetic and do not prove production integrations.

## Reproduce

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python scripts/v4_gate_engine.py validate-claim --input path/to/claim.json
python scripts/v4_gate_engine.py validate-artifact --input path/to/artifact-envelope.json
python scripts/v4_gate_engine.py evaluate --project path/to/project.json --output build/gate-report.json
python scripts/v4_gate_engine.py evaluate --project path/to/project.json --require-release
python scripts/v4_gate_engine.py invalidation-plan --project path/to/project.json --changed SRC-001
python scripts/v4_gate_engine.py hash --input path/to/record.json
```

| G7_RELEASE_APPROVED | CTRL-ARTIFACT-QA, CTRL-ACCESSIBILITY-QA, CTRL-RELEASE-APPROVAL | Real in-root file bytes/hash, supplied QA evidence, accessibility reviewer and hash-bound release signoff |

The gates execute sequentially. A non-PASS predecessor blocks subsequent gates. NOT_RUN, NOT_VERIFIED, BLOCKED, PARTIAL, STALE and INVALIDATED are never coerced to PASS. NOT_APPLICABLE must include an explicit rationale.

## Canonical hashing and provenance

Canonical JSON is UTF-8, NFC normalized, LF newline normalized, key-sorted and compact. Top-level `content_hash` is excluded when computing a self-hash. A SHA-256 proves byte identity only, not truth, source authority, rights or human approval. A source record must contain URI, retrieval timestamp, snapshot SHA-256 and snapshot text or a contained snapshot file whose bytes reproduce the hash.

Material health claims require a clinician review record. The approval registry must resolve the named reviewer to an active CLINICIAN role, authority evidence and signature-evidence reference. The approval must bind to that claim's own source-hash set. This is structural validation only; it does not independently authenticate identity, credentials, authority or digital signatures.

## Tests and CI evidence

The pytest suite exercises schema constraints, all 21 named controls, positive synthetic end-to-end evaluation, fail-closed transitions, source integrity, clinical approvals, safe wording, visual/prompt boundaries, frame errors, manifest tampering/path traversal, renderer capability, static-check evidence, artifact hashes, accessibility/release approval and dependency invalidation. CI archives JUnit XML, package validation summary, 1,000 candidate IDs and blocked gate report.

A blocked synthetic fixture must produce a non-zero `--require-release` exit, eight gate results, and `release_eligible=false`. This tests guard behavior, not readiness of a real campaign.

## Honest limits

The 10×10×10 generator yields 1,000 candidate definitions—not 1,000 executed tests. The executable set is 21 controls. Prompt injection scanning is heuristic; identity and credentials are not authenticated; accessibility and rights evidence content is not inspected; capability records do not run a renderer; artifact inspection checks bytes/hash and supplied evidence, but does not decode MP4. Live ChatGPT, external AI/ASR/diarization, TTS, Remotion integration and render, real video/audio QA, accessibility user testing and human clinical/legal/privacy/release approvals remain NOT_RUN/NOT_VERIFIED until real evidence exists.

A deterministic local PASS does not authorize public release. Keep public distribution HOLD until CI, independent review, runtime/media evidence and authorized human approvals are complete.


## Risk and applicability triage for the 1,000 candidate controls

Run the control enumerator, then run the separate risk triage script against the generated JSON. It scores each candidate using severity, likelihood and escape-difficulty weights, then sorts P0–P3 and labels CORE, CROSS_CUTTING or CONDITIONAL applicability candidates.

These labels are prioritization hints only. They do not decide that a control is applicable or not applicable to a real project. Every row is retained with NEEDS_PROJECT_REVIEW, NOT_RUN and NOT_VERIFIED. The heuristic weights must be calibrated by clinical, security, QA and production owners before they are used for operational risk acceptance. Unknown taxonomy fails closed.

The CI pipeline now runs this triage and stores its JSON output alongside the enumerated candidate registry. Enumeration and triage are not control execution.

## Prompt-injection red-team regression

The red-team fixture includes instruction override, hidden-prompt disclosure, credential exfiltration, safety-policy override, role-switching, and common HTML entity, URL-encoding, zero-width and full-width Unicode variants, with benign control examples. The detector normalizes these obfuscations before applying heuristic patterns.

A detection is a reason to hold the prompt for review, not a definitive classification of attacker intent. A no-match is not a safety proof. The core protection remains trusted/untrusted input separation, explicit delimiting, least-privilege tool access, human review and runtime security controls.
