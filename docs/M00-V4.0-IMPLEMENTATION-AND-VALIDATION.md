# M00 V4.0 — Executable validator and gate engine

**Implementation status:** deterministic Python engine implemented; 21 unique controls across eight gates; 47 synthetic unit/adversarial tests pass locally. GitHub Actions is configured to run package validation, all pytest tests, candidate-control generation, and a fail-closed CLI smoke test. This does not establish production readiness.

## Quick start

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python scripts/v4_gate_engine.py validate-claim --input path/to/claim.json
python scripts/v4_gate_engine.py validate-artifact --input path/to/artifact-envelope.json
python scripts/v4_gate_engine.py evaluate --project path/to/project.json --output build/gate-report.json
python scripts/v4_gate_engine.py evaluate --project path/to/project.json --require-release
python scripts/v4_gate_engine.py invalidation-plan --project path/to/project.json --changed SRC-001
python scripts/v4_gate_engine.py hash --input path/to/record.json
```

The CLI emits an auditable JSON report. Add `--require-release` for a non-zero exit unless all eight gates PASS. `invalidation-plan` is plan-only and never mutates artifacts.

## Executable gates and controls

The engine evaluates 21 named controls in strict sequential order. A downstream gate is BLOCKED unless its predecessor is PASS. NOT_RUN, NOT_VERIFIED, PARTIAL, BLOCKED, STALE and INVALIDATED are never converted to PASS. NOT_APPLICABLE is accepted only with an explicit rationale.

| Gate | Control IDs | Deterministic oracle |
|---|---|---|
| G0_INTAKE_OK | CTRL-INTAKE-INVENTORY, CTRL-PRIVACY-CLASSIFICATION, CTRL-RIGHTS-BASIS, CTRL-UNTRUSTED-INPUTS | Input inventory, privacy enum, rights basis/rationale, untrusted-input delimiter and byte hash |
| G1_FACT_LOCK | CTRL-CLAIM-SCHEMA, CTRL-SOURCE-PROVENANCE, CTRL-MATERIAL-CLAIMS, CTRL-CLINICAL-APPROVAL | Draft 2020-12 schema + semantics, source snapshot/hash, claim/source links, reviewer-matched hash-bound approval |
| G2_NARRATIVE_LOCK | CTRL-NARRATIVE-TRACEABILITY, CTRL-SAFE-WORDING | Claim ID traceability and exact allowed phrase matching |
| G3_VISUAL_LOCK | CTRL-CONTINUITY-LOCKS, CTRL-VISUAL-REFERENCES | Canon hash/evidence and scene reference resolution |
| G4_PROMPT_PREFLIGHT | CTRL-PROMPT-INJECTION, CTRL-PROMPT-BOUNDARY | Heuristic injection scan and explicit source-data boundary |
| G5_MANIFEST_VALID | CTRL-SCENE-TIMING, CTRL-MANIFEST-INTEGRITY | Contiguous frame/fps arithmetic, schema, canonical hash, safe paths |
| G6_CODE_VALID | CTRL-CAPABILITY-VERIFICATION, CTRL-CODE-STATIC | Exact renderer/provider/version capability record and evidenced static checks |
| G7_RELEASE_APPROVED | CTRL-ARTIFACT-QA, CTRL-ACCESSIBILITY-QA, CTRL-RELEASE-APPROVAL | In-root artefact byte/hash, QA record, accessibility reviewer evidence, hash-bound producer approval |

## Canonical hash and provenance

Canonical JSON uses UTF-8, NFC-normalized strings, LF newlines, sorted keys, compact separators, and excludes the top-level `content_hash` when computing the self-hash. SHA-256 proves byte identity only—not truth, origin, rights, authority or approval.

Each cited source needs a URI, retrieval timestamp, SHA-256, and inspectable snapshot text or safe in-project snapshot path whose bytes hash to that value. A bare hash assertion is rejected. Every material health claim needs a clinical approval matching its reviewer identity and source hash set.

Approval checks are structural: approver IDs must resolve to an active role record, with authority and signature evidence references, timestamp and hash binding. The engine does not authenticate identity, credentials, delegation, cryptographic signatures or the contents of the authority evidence. Production use must bind this register to a trusted identity/approval system.

## Reproducible tests

The tests use synthetic fixtures and negative/mutation cases for schema constraints, source provenance, material health claims, claim-by-claim clinical approval, narrative traceability, safe wording, visual continuity, prompt injection, untrusted prompt boundaries, frame gaps/overlaps, manifest hash/path traversal, renderer capability, static-code evidence, artifact hashes, accessibility, release approval, dependency graph cycles and transitive invalidation. CI runs the same pytest suite and stores JUnit XML, the package-validator report, control candidate index, and blocked gate report as build artefacts.

The blocked fixture intentionally contains UNKNOWN privacy and rights states. CI expects `--require-release` to return exit code 1 and verifies all eight gates are present and release eligibility is false. This validates fail-closed behavior, not a successful production project.

## 10×10×10 candidate model

The enumerator generates 1,000 unique candidate IDs (10×10×10). These are planning candidates; none have been executed by enumeration alone. The executable subset currently consists of the 21 controls listed above. Every future candidate must receive a control specification, threat/applicability rationale, deterministic oracle, positive and negative tests, evidence format and remediation path before it can count as implemented.

## Known limits — not proven by unit tests

- Prompt-injection matching is heuristic and has false positives/negatives; it does not prove safety or model behavior.
- Approval records are not independent proof of reviewer identity, licence, institutional authority or signature authenticity.
- Rights and accessibility evidence references are structurally checked; the engine does not contact the institution or perform a user study.
- Artifact QA verifies local file existence and hash plus supplied inspection evidence references. It does not decode or perceptually inspect MP4.
- Capability status checks a supplied registry record; it does not execute Remotion or verify a running renderer.
- Live ChatGPT use, external AI, ASR/diarization, TTS, actual Remotion integration/render, codec/stream inspection, media QA, accessibility user testing, formal legal/rights review and final human release approval remain separate and must remain NOT_RUN/NOT_VERIFIED/BLOCKED until real evidence exists.
- This implementation does not yet have a trusted enterprise identity provider, immutable append-only audit database, central source snapshot store or production sandbox.

A successful local pytest run proves only the tested deterministic logic against synthetic fixtures. It does not authorize public release. Keep PR #3 Draft until CI, review, external runtime/media evidence, clinical/legal/privacy and human approval requirements have been satisfied.
